# v1.3.0 — Reliability and honest usage measurements

这是一次可靠性与统计口径更新，而不是“统计数字越大越好”的功能发布。

## Highlights / 主要改进

- **API requests ≠ assistant messages**: Cursor fallback message counts are no longer described as billed API requests. Missing tokens are unknown; unattributed tokens are not allocated to models by cost share.
- **Schema-aware OpenCode collection**: inspect table/column availability and deduplicate message IDs across old/new storage; modern rows without usage can retain valid legacy measurements.
- **Safer ledger writes**: cross-process lock, read disk again before reducing scans, atomic writes, independent backup rotation and validated recovery. Damaged files are retained as evidence rather than silently replaced with empty data.
- **Data-quality diagnostics**: coverage of parsed observations, last successful scan, retained last-good data and stale status.
- **Owner-authenticated routes**: all plugin HTTP endpoints require DSH owner admission. CSV export is POST; Origin checks are not treated as authentication.
- **Panel recovery**: React error boundary and real ReactDOM regressions exercise all six views, filtering, language changes, HTTP failures and child-render failures.
- **Bounded scanning**: at most three collectors at once, with dependency diagnostics.

## Install / 安装

Requires **DSH >= 0.2.2-rc.3**, macOS-oriented source paths, and `sqlite3`, `jq`, `zstd`.

```sh
dsh plugin --profile web add github:skyzhao1223/dsh-agent-token-stats
```

For Desktop, use the running application's **Plugins → Add plugin** and the GitHub repository address. Do not manually edit profile YAML. Apply/update behavior depends on the running manager's result; refresh the page for client changes, and restart only if it reports that a restart is required.

The release tarball contains the prebuilt Host/Client files; no runtime React/jsdom development dependencies are required. **No npm publication is claimed.**

## Verification / 验证范围

- 18 Host regressions: real SQLite, independent writer processes, backup/recovery, retained data and full-route admission tests.
- 9 real ReactDOM/jsdom regression groups, plus 39 existing structural UX assertions.
- Isolated cold-open, cooldown, currency/pricing and traffic-archive tests.
- GitHub-hosted CI could not start for this release preparation (runner/account restriction, before any test step). Local tests passed; automated Linux/macOS runner validation remains pending. This release is kept as a draft until that verification is available.
- Local current-profile activation returned `applied`; unauthenticated checks on all five live routes returned 403.
- Public screenshots are synthetic demo data rendered by the actual v1.3 client, not private usage and not live-GUI pixel acceptance.

## Important boundaries / 重要边界

- Historical ledger rows are **preserved, not destructively recomputed**. Older uncertain count semantics are disclosed. Use the read-only ledger diff tool before any corrective migration.
- Aggregate high-water accounting cannot prove exact new events after source-log rotation; event-level accounting remains roadmap work.
- Coverage of parsed records is not proof that original logs are complete. Source versions may omit usage fields.
- Dead/orphan locks require inspection; they are not automatically stolen. Linux source compatibility has not been fully validated, and Windows scanning is not supported.
- Reported fees and reference estimates are separate and are not subscription invoices.

## Privacy and contribution
